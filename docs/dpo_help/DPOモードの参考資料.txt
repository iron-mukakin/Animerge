
「SDPOは過学習全般を抑制する」という理解は不正確。SDPOが保証しているのはもっと狭い、特定条件下でのwin側品質の保護であり、汎用的な過学習対策(正則化・early stopping・容量制限など)とは別物。むしろ今回の会話で得た実ログがその反証になっている。
DPOとSDPOの実装上の差分
現在の実装(compute_dpo_loss)では、両者はまったく同じ損失関数から出発し、lose側のみが異なる。
DPO  : L = -log σ(-β · (L^w - L^l))
SDPO : L = -log σ(-β · (L^w - L^l_scaled))
       L^l_scaled = L^l.detach() + λ_safe · (L^l - L^l.detach())
重要な点として、L^l_scaledはforward値がL^lと数値的に完全に同一になるよう設計されている（straight-through方式）。つまり:

loss/win_loss/lose_lossとしてログ・グラフに出る数値は、同一データ・同一seedであればDPOでもSDPOでも見た目上まったく同じになる
違いが生じるのはbackward時のlose側勾配の大きさだけ。g^wᵀg^l > 0（lose側の勾配方向がwin側の損失を悪化させる向き）のときだけλ_safe<1となり抑制がかかる。g^wᵀg^l ≤ 0（本質的に安全な状態）ならλ_safe=1でDPOと完全に一致する

つまりSDPOは「別の損失関数」ではなく、「DPOの勾配計算に条件付きブレーキを1つ足しただけ」というのが実態に近い。
「過学習抑制」という理解への反論
SDPO論文(SDPO.txt)が明示的に解決しようとしている問題は、以下のように限定的に書かれている。

従来のDiffusion-DPOは...過剰になると勝者側の生成品質まで悪化（Lossが上昇）させる問題があります

これは「lose側を強く押し下げようとする勾配が、win側の損失まで巻き添えで悪化させてしまう」というwin/lose間の勾配の対立(collateral damage)を防ぐ仕組みであり、以下のようなものとは別物：

過学習そのもの（訓練データへの記憶・汎化性能の低下）を防ぐ正則化ではない
重み減衰・EMA・early stopping・LoRA容量制限のような、一般的な過学習対策の代替にはならない
保証しているのは「ΔL^w ≤ 0（winの損失が悪化しない）」というwin側1指標だけの局所的な安全条件であり、モデル全体の汎化やドリフトを保証するものではない

そして、この会話の実ログがまさにその限界を示す直接的な反証になっている。 前回のSDPO学習ではλ_safeが0.44〜0.71で継続的に発動し（＝lose側勾配は実際に30〜56%抑制され続けていた＝SDPOの安全機構は正常に作動していた）、それでも出力画像は全体的にドリフト（暗転）した。これは、SDPOのwin保護機構がターゲットとしている失敗モード（win/lose勾配の対立によるwin品質劣化）と、実際に発生した失敗モード（diff_mask未使用によるグローバル信号への過学習）がまったく別の原因であるため、SDPOを使ってもドリフト自体は防げなかったことを意味する。SDPOは「lose側を叩きすぎてwinまで巻き添えにする」ことは防ぐが、「win/loseの弁別信号が希薄なまま学習全体が意図しない方向に流れる」ことは防がない。
実際に優れている点・優れていない点の整理
観点DPOSDPOwin/lose勾配が対立する場合のwin品質劣化対策なし（起こり得る）λ_safeで緩和lose側が十分「安全」な場合(g^wᵀg^l≤0)の挙動通常通りDPOと完全一致（追加コストなし）学習データ全体への過学習・単一ペアへのドリフト対策なし対策なし（今回のログで実証済み）diff_mask未使用時のwin/lose弁別信号の希薄化対策なし対策なし（そもそも計算対象が同じ）計算コスト基準ほぼ同等（出力空間の残差ベクトルのみ、追加のバックワード不要）
したがって「SDPOの方が優れている」と言えるのは、win/lose間の勾配対立が実際に発生する状況（マスク適用済み・複数ペア・win側がreferenceより悪化しやすい設定など）に限定した話であり、「過学習しにくい」という一般的な性質として語るのは実装・論文の主張いずれから見ても言い過ぎ。今回のような単一ペア・マスクなしのドリフト対策としては、SDPOへの切り替えではなく前回提案した--diff_use_diff_mask＋--mask_bg_weightの方が直接的に効く対策になる。lose側の悪化がwin側を侵食して壊す防波堤ありがSDPOという認識で正しいか？ユーザーの直感を検証し、勾配競合の本質を精密化した。ユーザーの直感を検証し、勾配競合の本質を精密化した。概ね正しい認識だが、精度を上げると以下のようになる。
「防波堤」のたとえの正確な範囲
正確には「lose側を押し下げる勾配が、win側の損失まで悪化させる方向に働いている場合に限り、その勾配を弱める防波堤」。lose側の悪化そのものをブロックするわけではない。

lose側の損失は普通に計算され、通常のDPO同様に働き続ける
ブロックされるのは「lose側を叩く勾配 glg^l
gl が、たまたまwin側の勾配 gwg^w
gw と同じ向き（gw⊤gl>0g^{w\top}g^l>0
gw⊤gl>0）を向いていて、結果的にwin側の損失まで押し上げてしまうケース」だけ
逆にgw⊤gl≤0g^{w\top}g^l \le 0
gw⊤gl≤0（lose側を叩いてもwin側に悪影響しない、本質的に安全な状態）なら防波堤は完全に開放され、λ_safe=1でDPOと同じ挙動になる

「壊す」の意味も限定的
侵食・破壊されるのはモデル全体の品質ではなく、win側の損失指標（Lw\mathcal{L}^w
Lw）が学習前より悪化するという1点のみを指す。win側の生成品質全体の劣化や、モデルの汎化性能低下を包括的に守るものではない。
防波堤は「せき止める壁」ではなく「可変バルブ」
もう一つ訂正したい点として、「防波堤」というと0/1の遮断のようなイメージになりがちだが、実際はλsafe∈[0,1]\lambda_{safe} \in [0,1]
λsafe​∈[0,1]の連続的な減衰係数であり、対立の強さに応じて滑らかに絞る仕組み。全く通さない（λsafe=0\lambda_{safe}=0
λsafe​=0）ケースはクリップの下限に達したときのみで、多くの場合は部分的に減衰させるだけ。
まとめると：**「lose側の勾配がwin側を巻き込んで悪化させる、その一点だけを狙い撃ちして弱める可変式の安全弁」**という理解が最も正確。「防波堤」という比喩自体は方向性として正しいが、対象が「lose側の悪化全般」ではなく「win側への巻き添え」に限定されている点、および0/1ではなく連続的に効く点を押さえておくと、前回示したように「防波堤があるのにドリフトした」ことの理由（＝ドリフトはwin側巻き添えとは別ルートで起きた）も矛盾なく理解できる。

- MaPOの利点(学習内容のみ、速度・VRAM除く)
前提を先に訂正しておく。ここまでの会話で明らかになった「マスク未使用時のドリフト」「win/lose弁別信号の希薄化」は、MaPOに変えても解決しない。両モードともwin/lose双方のMSEを同じ範囲(マスク適用時はマスク内、未適用時は全体)で計算する構造は共通のため、この根本問題は損失関数の選択とは独立している。その上で、学習内容として実際に異なる点は以下の3つ。
1. 明示的なSFTアンカーの有無(最も本質的な違い)
DPO/SDPOの損失は-logσ(-β·delta_error)のみで構成され、win画像そのものを再現しようとする項が存在しない。実際に前回の実測ログでdelta_error≈0(win/lose弁別ほぼゼロ)の状態が続いた際、損失値はln2付近で平坦になり、「winに似せる」という直接的な引力は一切働いていなかった(勾配自体はsigmoid(0)=0.5により大きく流れ続けていたが、その勾配の向きはwin/loseの相対比較のみに由来し、winへの収束を保証するものではなかった)。
MaPOは総損失にLMSE(win)\mathcal{L}_{\text{MSE}}(win)
LMSE​(win)を独立項として常に含む。マージン項が仮に機能しなくなった(弁別信号が薄い)としても、win画像へ向かう再構成誤差最小化の圧力は構造的に消えない。つまり**「最悪でも通常のSFTとしてwinには収束する」という下限保証がある**。これはDPO/SDPOにはない性質。
2. 有界リンク関数による暗黙報酬の発散抑制(論文の本来の主眼)
MaPO.txtが有界リンク関数ϕβ\phi_\beta
ϕβ​を導入する動機として明記しているのは「DPOのインプリシット・リワードのように報酬値が無限に発散して過学習を起こすのを防ぐ」こと。DPO/SDPOのdelta_errorは理論上無制限に増大しうる値で、実際に前回のログでもwin_deltaは0から-0.93まで単調に増大し続けており、上限は見えなかった。
MaPOのϕβ(L)∈(0,1]\phi_\beta(\mathcal{L}) \in (0,1]
ϕβ​(L)∈(0,1]は必ず有界であり、winが十分低損失・loseが十分高損失に達すると、マージン項がそれ以上際限なく強化される余地が構造的になくなる(飽和する)。これは単一ペア学習で過学習が進みやすいという今回のユースケースに対して、SDPOのλ_safeとは異なる種類の歯止めとして機能しうる。SDPOはあくまで「lose側勾配がwinを巻き添えにする局所的な対立」だけを抑えるが、MaPOのこの機構は「弁別信号そのものの振幅」に上限を課す、より一般的な安全装置である。
3. 見落としてはいけないトレードオフ: 暗黙の事前分布アンカーの喪失
DPO/SDPOはdelta_error = (loss - ref_loss)という設計上、delta_error≈0が「事前学習済みモデルの挙動から離れていない」ことを意味する。これは明示的に書かれてはいないが、reference比較という構造そのものが「基準モデルの知識から逸脱しすぎない」という暗黙の正則化を無償で提供している。
MaPOはreferenceを一切参照しないため、この暗黙のアンカーが完全に失われる。上記1・2の仕組み(SFTアンカー・有界マージン)だけでこの役割を代替する必要があり、特にmapo_bg_weight(前回実装した正解ノイズ基準の背景正則化)を有効にしない場合、基準モデルからの逸脱を抑える仕組みが実質的に存在しなくなる点は明確なデメリットとして認識しておくべき。
結論
学習内容の観点でMaPOを選ぶ合理性があるとすれば、「winへの収束保証」と「弁別信号の発散に対する構造的な上限」の2点に限られる。ただし「基準モデルからの逸脱を抑える暗黙の仕組みを失う」という代償を伴うため、優劣関係ではなく異なる保護特性を持つ選択肢と捉えるべきで、今回一貫している根本課題(diff_mask運用)を解決する手段ではない。
